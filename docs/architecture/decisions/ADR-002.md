# ADR-002: Use a JSON document map and standard-library checker

**Status:** proposed.
**Evidence basis:** present implementation.
**Deciders:** awaiting maintainer review.

## Context

The optional checker needs structured metadata and predictable errors.
Normal plugin users should not need a package installation.

## Choice implemented

Store metadata in one `map.json` file beside the handbook.
Use Python's standard JSON parser with duplicate-key and schema checks.
Do not implement a partial YAML parser.

| Alternative | Benefit | Cost |
|---|---|---|
| YAML frontmatter and external parser | Metadata next to each page | Extra runtime dependency |
| Custom YAML subset parser | No dependency | Ambiguous syntax and maintenance risk |
| JSON map | Explicit schema, no extra packages | Separate map requires maintenance |

## Consequences

Authors must register pages and maintain coverage patterns.
A separate map can also register existing documents in place, such as `../ARCHITECTURE.md`,
without editing them. Frontmatter could not do that.
The checker can detect missing entries, but not every semantic dependency.
The single map can become large. The agent should query it rather than load it wholesale.

## Reversal cost and review trigger

A format change requires a migration and backward-compatibility policy.
Review this choice if real projects show map size or merge conflicts as a persistent problem.
