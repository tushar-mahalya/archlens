# ADR-001: Use manual, isolated commands

**Status:** proposed.
**Evidence basis:** current implementation and user request for low context cost.
**Deciders:** awaiting maintainer review.
**Superseded in part by:** [ADR-003](ADR-003.md), which adds a passive map and hooks.

## Context

Architecture work can require large source traces.
Loading all guidance into every coding session wastes context.
The user also needs predictable control over documentation edits.

## Choice implemented

For the native Claude plugin, provide five explicit commands using manual invocation and a forked task.
Keep a small shared contract and conditionally load detailed sections.
Use bounded local reports before reading source.

| Alternative | Benefit | Cost |
|---|---|---|
| Global instruction handbook | Always available | Persistent context, irrelevant detail |
| Auto-discoverable skill | Convenient activation | Description overhead and uncertain invocation |
| Manual isolated command | Explicit scope and bounded parent result | User must remember to run it; worker has startup cost |

The native Claude implementation uses the third option.
The portable Agent Skill instead uses a small router and one selected workflow.
Portable hosts can discover or invoke it automatically and need not provide isolation.
This tradeoff makes the method available outside Claude without claiming identical host behavior.
This record is not a claim of human acceptance.

## Consequences

In the native plugin, the worker does not receive prior conversation history.
Users should supply decision evidence explicitly in either distribution.
A separate worker still consumes tokens. A portable host may use the current conversation.
Tiny questions may be cheaper in normal chat.

## Validation and review trigger

[Prompt budgets](../../../tools/prompt_budget.py) guard instruction growth.
[Summary tests](../../../tests/test_archlens.py#L910-L928) guard output size and omission counts.
Actual model-task tokens and semantic quality still need the [evaluation plan](../../context-efficiency.md).
Revisit if measured overhead exceeds the benefit for typical architecture tasks.
