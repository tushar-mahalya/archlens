A-000 Cover sheet · Living architecture docs for Claude Code and AI coding agents

Architecture docs that stay in sync4 with your code.

Archlens keeps your architecture docs in step with your code. It writes a small handbook, or adopts the docs you already have where they live. It gives your coding agent a map of the whole project in a few hundred tokens, and teaches you the codebase while you work. It runs as a Claude Code plugin and as a portable Agent Skill for Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, and other agents.

Install see I-601 Read the Archlens source on GitHub

General notes

  1. Every claim links to source, tests, or decisions. Unknowns stay unknown.
  2. Drift detection is a local Python script. It uses no model tokens.
  3. Docs update once per commit, and land in the same commit as the code.
  4. No server, no telemetry, no network calls. Python 3.9+ enables hooks and checks.
  5. MIT licensed. Independent project.

A-101The problem

Docs go stale a week after they are written. Agents start from zero every session.

Nothing says which architecture page drifted, and nothing tells a coding agent where to look, so it explores the repository again. Archlens answers both with one small handbook, or the docs you already have, and a baseline for every page.

Schedule of problems

Archlens starts small: context, main units, and one important journey, then grows by risk. Pages use Mermaid diagrams, short sentences, and plain words.

When a project already has architecture docs, setup adopts them. Nothing moves or gets copied. Mapped docs get the same link and reference checks and freshness tracking, and they appear in the agent’s page map. setup new writes a separate handbook instead.

Pages cite evidence, often a line range such as order_service.py#L20-L38. sync records a baseline of the function around each range. Python uses its syntax tree. JavaScript, TypeScript, Go, Rust, Java, C#, C/C++, Swift, PHP, Dart, and other C-family languages use a comment- and string-aware brace reader 4. It is a heuristic, not a parser. Comments and formatting do not count, and a moved function is followed.

A range inside a larger function tracks only its own lines. One changed rule in a 40-line function no longer flags every citation inside it.

Cited evidence that changed makes a page stale. A whole-file link to code goes stale only when the file’s declared names change; body edits mark it for review, as ADR-001 shows. An edit to a linked Markdown document marks review; deleting a linked file marks stale. Comment-only edits never make a page stale.

Links follow the code with no model. Moved code, files Git reports as renamed, and citations shifted by a new comment inside a function are rewritten. When a cited function disappears, status suggests a likely rename, such as symbol-removed memory.py#L14-L19 (authorized) now `is_authorized`?

cite prints a link-ready range for a symbol, so pages cite exact lines. check warns when a range cuts off a function’s first or last code line by one or two lines.

A stale flag means “check this page”. It does not prove the prose is wrong.

A-201The loop

Detecting drift costs no tokens. Rewriting prose happens only where it drifted.

Archlens separates two jobs. A local script compares the code each page cites with the baseline recorded at its last sync, and rewrites links whose code only moved: no model, no tokens. An agent then reviews only the stale pages, edits what changed, and syncs the pages it verified. By default that happens once per commit, so the docs land in the same commit as the code.

Keyed notes

  1. Session start. In a project with a handbook, a SessionStart hook prints the page map: one line per page, with stale flags. The budget is 3,000 bytes by default; this repository’s map is 1,630 bytes, about 408 tokens. Summaries come from a page’s “Summary” section when it has one. Projects without a handbook get nothing.
  2. Agent works. The map says where to look. When the agent reads or edits a documented file, a hook names that file’s page, once per page per session. Pages summarize; source is authoritative.
  3. Stop hook and commit gate. 4 When a turn ends, a local script compares cited evidence with its baseline. Code that only moved, or a file Git reports as renamed, gets its links rewritten. Code that changed makes the page stale, and you see one line per new set of stale pages. 276 ms on a 50,000-file repository. Before Claude runs git commit, a PreToolUse hook holds the commit once if it would leave pages stale.
  4. Update. With "autoUpdate": "commit" (the new default), the held commit runs the update first, in an isolated task. With "auto", it runs at the end of every turn. It fixes stale pages first, confirms review pages, and changes only prose the change made wrong.
  5. Sync. sync records the reviewed pages’ new baseline and refreshes the context file. It trusts the caller, so only pages someone checked against current source get synced. Then the commit runs again, and code and docs land together.

When docs update 4

In every mode except off, the hooks first rewrite line links whose cited code only moved. Commits you make yourself in a terminal are not held: the turn-end message and the archlens-stale pre-push hook catch them. You add nothing to CLAUDE.md. The hooks are deterministic and cost no context until a page is actually stale. Other agents get the same rule through the AGENTS.md block.

1 Revision note

What the first run taught us

The first map told agents to “read pages before source”. They treated a page summary as the whole answer. One answer said it had “only read the README” and never opened the generator. Recall fell to 80%, against 90% without a handbook. That run is published too.

Two fixes closed the gap:

  1. The map now says “Pages summarize; source is authoritative.”
  2. The run exposed a real coverage gap: one table row covered how the portable skill is generated. A distribution page now covers it, and portable-sync recall rose from 17% to 100%.

A thin page can make an agent less thorough than no page.

! Finding

Setup found a real bug

The web client’s messages for HTTP 503 and 504 can never show on the streaming endpoint.

Capacity and deadline failures arrive as an in-stream error event, after the server has already sent HTTP 200.

What the trial changed

  • Style heuristics became one info note per page. Findings sort errors first.
  • Git-ignored paths, never-tracked names such as the MCP method tools/list, and paths in accepted decision records are no longer reported as stale references.
  • After the precision changes, the same code change flags 2 citations instead of 6. A comment-only edit no longer makes the glossary stale.
  • Editing a linked Markdown document marks pages for review, not stale. A docs fix that flagged 5 pages stale now gives 0 stale, 5 review.
  • check warns when a line range cuts off a function’s first or last code line by one or two lines. It found 1 real case, a test citation that dropped the finally: slot release, and no false positives.

Limits of this trial

  1. One trial on one repository. It is not a general benchmark, and your times and costs will differ.
  2. Times and costs are from Claude Code headless on Opus.
  3. The runtime page was checked by sampling its claims, not line by line.
  4. The repository is not named here. The 72-session benchmark on A-301 is the published, rerunnable measurement.

A-501Learn

Understand the code, not just ship it.

/archlens:learn is a patient tutor. It answers from handbook pages first, reads source to confirm or fill a gap, cites both, and labels inference and unknowns. It runs inline, so you can ask follow-ups.

Four modes

/archlens:learn how are duplicate orders prevented?
Answers from the handbook first, with source links, in at most 150 words. Then one real trace or snippet.
/archlens:learn tour
Walks the reading path one stop per turn and waits before the next.
/archlens:learn quiz data flow
One question at a time about real behavior here. Grades each answer against evidence. Stops after five with a score and the pages to reread.
/archlens:learn changes
Explains what the current branch changes, which flow or data it affects, and why it matters.

While a long task runs, Claude Code’s /btw can answer from the page map already in context. In the real-project trial (A-302), one tutor answer took 45 seconds and $0.32.

I-601Install

Three lines in Claude Code. One line everywhere else.

No API key, Node installation, or server is required for the Claude Code plugin. Python 3.9+ on PATH as python3 enables the hooks and checks (the macOS system Python works); the commands still run without it. Your agent’s normal subscription or API usage still applies.

Claude Code plugin

Run these inside Claude Code. Choose user scope when asked, so Archlens works in every project.

/plugin marketplace add tushar-mahalya/archlens
/plugin install archlens@archlens
/archlens:setup

That is all. If the project already has architecture docs, setup adopts them where they live (/archlens:setup adopt, the default then). Otherwise, or with /archlens:setup new, it writes a handbook under docs/architecture/. It records a freshness baseline. From then on the docs update once per commit, in the same commit as the code. You add nothing to CLAUDE.md.

From a terminal, the install equivalent is claude plugin marketplace add tushar-mahalya/archlens then claude plugin install archlens@archlens --scope user. Choose either the native plugin or the portable skill for Claude Code, not both.

Codex, Cursor, Copilot, Gemini CLI, and others

The portable Agent Skill installs with skills.sh. In the project directory, with Node.js 22.20+ and Git:

npx skills@1.7.6 add tushar-mahalya/archlens --skill archlens --agent codex --copy --yes

Replace codex with cursor, github-copilot, gemini-cli, opencode, roo, or devin, or add --global for a user-level installation. Then ask your agent:

Use the Archlens skill to set up architecture documentation for this project.

Setup offers to write the page map into AGENTS.md, which these agents read every session. To write it yourself, set { "contextFile": "AGENTS.md" } in .archlens.json and run:

python <skill-dir>/scripts/archlens.py context --root . --write

Every sync refreshes the block. The written block has no stale flags, because freshness changes between commits; it tells the agent to run the status check before relying on a page, and to update stale pages before it commits code, in the same commit. Portable hosts do not necessarily provide Claude’s isolated, manual-only behavior. The skills CLI has its own telemetry; set DISABLE_TELEMETRY=1 to opt out. See installation for adapters and caveats.

Git hooks with pre-commit

Works with any editor or agent. Add Archlens to .pre-commit-config.yaml:

repos:
  - repo: https://github.com/tushar-mahalya/archlens
    rev: v0.4.0
    hooks:
      - id: archlens-check   # links, anchors, diagrams, stale references
      - id: archlens-stale   # on pre-push: fail while cited code changed

Install both stages:

pre-commit install --hook-type pre-commit --hook-type pre-push

archlens-check runs on every commit and fails on structural errors. archlens-stale runs on pre-push and fails while covered source changed after the last sync. rev: v0.4.0 pins the latest release.

CI check on pull requests

This GitHub Actions job fails a pull request whose code changes leave pages stale. Copy archlens.py into your repository first, for example as tools/archlens.py, or check out the Archlens repository in the job.

name: architecture-docs
on: pull_request
permissions:
  contents: read
jobs:
  freshness:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.13"
      - run: python tools/archlens.py check --root . --summary
      - run: python tools/archlens.py status --root . --fail-on-stale

To rewrite stale pages in CI, run your coding agent’s headless mode with the Archlens update operation and open a pull request for human review. Never let an automated job mark pages reviewed or decisions accepted.

Trust and limits

  • A stale flag means “check this page”. It does not prove the prose is wrong.
  • Code shows what happens, not why a person chose it. Decisions stay proposed until a human accepts them.
  • Python and C-family files get symbol-level fingerprints. The C-family brace reader is a heuristic, not a parser. Other files use normalized line-range text.
  • The benchmark covers one small repository. The real-project trial (A-302) is one trial on one larger repository. Coding-task results are not measured yet.
  • Archlens has no server, no telemetry, and no network calls. Your agent’s provider policy still applies.
  • The writing style is STE-inspired, not certified ASD-STE100.

Q-701Questions

Questions people ask before they install.

Short answers. Each one points to the sheet with the details.

What is Archlens?

Archlens is a Claude Code plugin and a portable Agent Skill that keeps architecture docs in sync with your code. It writes a small, source-linked handbook or adopts the docs you already have. A local script flags pages whose cited code changed, and an isolated task updates them, by default in the same commit as the code. It also gives your coding agent a page map of the project in a few hundred tokens.

How is Archlens different from DeepWiki or OpenWiki?

DeepWiki regenerates a hosted wiki and serves it through the web and MCP. OpenWiki ties claims to line-range evidence and updates through a manual run or a scheduled CI pull request. Archlens keeps the docs in your repository, detects drift on the exact functions and line ranges each page cites with a local script and no model, and updates only the stale pages. Its always-loaded map has a byte budget that CI enforces. The field survey (S-401) compares more tools; vendor claims there are as published.

Which coding agents does it support?

Claude Code gets the native plugin with hooks. Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, Roo, Devin, and other agents get the portable Agent Skill through skills.sh, and any agent that reads AGENTS.md can get the page map. The pre-commit hooks and the CI check work with any editor or agent.

Does it need a server, an API key, or send telemetry?

No. Archlens has no server, no telemetry, and makes no network calls. The Claude Code plugin needs no API key or Node installation; Python 3.9+ enables the hooks and checks. Your agent’s normal subscription or API usage and provider policy still apply. The skills CLI that installs the portable skill has its own telemetry; set DISABLE_TELEMETRY=1 to opt out.

What does keeping docs current cost?

Detecting drift costs no model tokens, because it is a local script. By default, prose is rewritten once per commit that leaves pages stale. In the real-project trial (A-302), an update after two real code changes took 93 seconds and $0.40 on Opus, and a whole change, test, and commit task with its docs took 4.6 minutes and $1.25. That is one trial on one repository.

Does it work with the docs I already have?

Yes. In a project with architecture docs, /archlens:setup adopt, the default then, maps them where they live, fixes statements the code contradicts with minimal edits, adds pages only for real gaps, and uses your decision-record folder and numbering. Mapped docs get the same checks and freshness tracking as new pages.

How do I install it?

In Claude Code, run /plugin marketplace add tushar-mahalya/archlens, then /plugin install archlens@archlens, then /archlens:setup. For other agents, run npx skills@1.7.6 add tushar-mahalya/archlens --skill archlens --agent codex --copy --yes in the project, and replace codex with your agent.
