A-101Why

Docs rot in a week. Agents start cold every session.

Archlens ties each page to the code it cites, so a script can tell which page drifted and your agent knows where to look.

  • The page knows when its code changed

    Each page cites functions and line ranges. A changed rule flags that page, even after the commit.

    226 of 226 real changes caught

  • Links follow moved code

    Code that only moved, or a renamed file, gets its links rewritten. No model, no tokens.

    81 of 81 moves followed exactly

  • Your agent starts with a map

    One line per page loads at session start. The agent opens the right file first.

    405 tokens for this whole repository

  • Claims point at source

    Pages link every important claim to code, tests, or a decision. Unknowns stay unknown.

    0.04 wrong claims per answer

A-201How

A script finds the drift. Your agent fixes only that.

Detecting drift costs no tokens. Prose is rewritten once per commit, and the docs land in the same commit as the code.

Five steps

  1. Session start. A hook prints the page map, with stale flags.
  2. Agent works. Open a documented file and the hook names its page and section.
  3. Commit gate. A script compares cited code with its baseline. Moved links are rewritten. A commit that would leave pages stale waits once.
  4. Update. An isolated task reviews only the stale pages.
  5. Sync. The reviewed pages get a new baseline. Code and docs commit together.

Double-lined boxes are local scripts: no model tokens.

Six commands

  • /archlens:setupWrite a handbook, or adopt your docs
  • /archlens:updateRefresh stale pages
  • /archlens:checkAudit links, evidence, diagrams
  • /archlens:explainTrace one flow with a diagram
  • /archlens:decideDraft a decision record
  • /archlens:learnTour, quiz, or ask the codebase

Five run in an isolated task, so exploration never fills your conversation. Command guide

Claude Code plugin

      
Run these inside Claude Code. Choose user scope when asked, so Archlens works in every project.

      
/plugin marketplace add tushar-mahalya/archlens
/plugin install archlens@archlens
/archlens:setup

      
That is all. If the project already has architecture docs, setup adopts them where they live (/archlens:setup adopt, the default then). Otherwise, or with /archlens:setup new, it writes a handbook under docs/architecture/. It records a freshness baseline. From then on the docs update once per commit, in the same commit as the code. You add nothing to CLAUDE.md.

    


    

      
Codex, Cursor, Copilot, Gemini CLI, and others

      
The portable Agent Skill installs with skills.sh. In the project directory, with Node.js 22.20+ and Git:

      
npx skills@1.7.6 add tushar-mahalya/archlens --skill archlens --agent codex --copy --yes

      
Replace codex with cursor, github-copilot, gemini-cli, opencode, roo, or devin, or add --global for a user-level installation. Then ask your agent:

      
Use the Archlens skill to set up architecture documentation for this project.

      
Setup offers to write the page map into AGENTS.md, which these agents read every session. To write it yourself, set { "contextFile": "AGENTS.md" } in .archlens.json and run:

      
python <skill-dir>/scripts/archlens.py context --root . --write

    


    

      
Git hooks with pre-commit

      
Works with any editor or agent. Add Archlens to .pre-commit-config.yaml:

      
repos:
  - repo: https://github.com/tushar-mahalya/archlens
    rev: v0.5.0
    hooks:
      - id: archlens   # one gate: fix moved links, check structure, stop when cited code changed

      
pre-commit install

      
The archlens hook runs on every commit. It rewrites links to code that only moved, fails on structural errors, and fails when a staged file changes code that a page cites. Pages that were already stale do not block the commit. rev: v0.5.0 pins the latest release.

    


    

      
CI check on pull requests

      
This GitHub Actions job fails a pull request whose code changes leave pages stale. Copy archlens.py into your repository first, for example as tools/archlens.py, or check out the Archlens repository in the job.

      
name: architecture-docs
on: pull_request
permissions:
  contents: read
jobs:
  freshness:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.13"
      - run: python tools/archlens.py check --root . --summary
      - run: python tools/archlens.py status --root . --fail-on-stale

Q-701Questions

    

      
Questions people ask before they install.

      
Short answers. The guide has the detail.

    

  


  

    
What is Archlens?
Archlens is a Claude Code plugin and a portable Agent Skill that keeps architecture docs in sync with your code. It writes a small, source-linked handbook or adopts the docs you already have. A local script flags pages whose cited code changed, and an isolated task updates them, by default in the same commit as the code. It also gives your coding agent a page map of the project in a few hundred tokens.

    
How is Archlens different from DeepWiki or OpenWiki?
DeepWiki regenerates a hosted wiki and serves it through the web and MCP. OpenWiki ties claims to line-range evidence and updates through a manual run or a scheduled CI pull request. Archlens keeps the docs in your repository, detects drift on the exact functions and line ranges each page cites with a local script and no model, and updates only the stale pages. Its always-loaded map has a byte budget that CI enforces. The comparison on A-401 compares more tools; vendor claims there are as published.

    
Which coding agents does it support?
Claude Code gets the native plugin with hooks. Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, Roo, Devin, and other agents get the portable Agent Skill through skills.sh, and any agent that reads AGENTS.md can get the page map. The pre-commit hooks and the CI check work with any editor or agent.

    
Does it need a server, an API key, or send telemetry?
No. Archlens has no server, no telemetry, and makes no network calls. The Claude Code plugin needs no API key or Node installation; Python 3.9+ enables the hooks and checks. Your agent’s normal subscription or API usage and provider policy still apply. The skills CLI that installs the portable skill has its own telemetry; set DISABLE_TELEMETRY=1 to opt out.

    
What does keeping docs current cost?
Detecting drift costs no model tokens, because it is a local script. By default, prose is rewritten once per commit that leaves pages stale. In the real-project trial, an update after two real code changes took 93 seconds and $0.40 on Opus, and a whole change, test, and commit task with its docs took 4.6 minutes and $1.25. That is one trial on one repository.

    
Does it work with the docs I already have?
Yes. In a project with architecture docs, /archlens:setup adopt, the default then, maps them where they live, fixes statements the code contradicts with minimal edits, adds pages only for real gaps, and uses your decision-record folder and numbering. Mapped docs get the same checks and freshness tracking as new pages.

    
How do I install it?
In Claude Code, run /plugin marketplace add tushar-mahalya/archlens, then /plugin install archlens@archlens, then /archlens:setup. For other agents, run npx skills@1.7.6 add tushar-mahalya/archlens --skill archlens --agent codex --copy --yes in the project, and replace codex with your agent.
