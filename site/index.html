A-000 Cover sheet · A drawing set for your codebase

Architecture docs that stay in sync3 with your code.

Archlens keeps a small architecture handbook in step with your code, gives your coding agent a map of the whole project in a few hundred tokens, and teaches you the codebase while you work. It runs as a Claude Code plugin and as a portable Agent Skill for Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, and other agents.

Install see I-601 Read the source on GitHub

General notes

  1. Every claim links to source, tests, or decisions. Unknowns stay unknown.
  2. Drift detection is a local Python script. It uses no model tokens.
  3. No server, no telemetry, no network calls. Python 3.9+ enables hooks and checks.
  4. MIT licensed. Independent project.

A-101The problem

Docs go stale a week after they are written. Agents start from zero every session.

Nothing says which architecture page drifted, and nothing tells a coding agent where to look, so it explores the repository again. Archlens answers both with one small handbook and a baseline for every page.

Schedule of problems

MarkWhat goes wrong todayWhat Archlens doesMeasured
P1Docs go stale a week after they are writtenFingerprints the exact functions and line ranges each page cites, and flags the page when that code changes, even after a commitChecks 50,000 files in 0.22 s
P2Moved code breaks every #L120 linkRewrites links whose cited code only moved. No model, no tokensAutomatic after each Claude turn
P3Agents re-explore the repository every sessionLoads a compact page map at session start, or writes it into AGENTS.md408 tokens for this repo; capped at 3,000 bytes
P4Context files bloat every turnOne model-visible description; everything else loads only when used178 bytes in every session
P5AI wikis invent plausible detailsEvery claim links to source, tests, or decisions. Unknowns stay unknown. A checker catches dead links, moved anchors, and vanished symbols0.04 wrong claims per answer in the benchmark
P6You ship code you do not understand/archlens:learn answers questions, gives a tour, quizzes you, and explains your branchInline, so you can ask follow-ups

Archlens starts small: context, main units, and one important journey, then grows by risk. Pages use Mermaid diagrams, short sentences, and plain words.

Pages cite evidence, often a line range such as order_service.py#L20-L38. sync records a baseline of every cited range and covered file. For Python, the baseline is the syntax tree of the function around the range, so comments and formatting do not count and a moved function is followed.

Cited evidence that changed makes a page stale. Changes elsewhere in covered files only mark it for review.

A stale flag means “check this page”. It does not prove the prose is wrong.

A-201The loop

Detecting drift costs no tokens. Rewriting prose happens only where it drifted.

Archlens separates two jobs. A local script compares the code each page cites with the baseline recorded at its last sync, and rewrites links whose code only moved: no model, no tokens. An agent then reviews only the stale pages, edits what changed, and syncs the pages it verified.

Keyed notes

  1. Session start. In a project with a handbook, a SessionStart hook prints the page map: one line per page, with stale flags. The budget is 3,000 bytes by default; this repository’s map is 1,630 bytes, about 408 tokens. Projects without a handbook get nothing.
  2. Agent works. The map says where to look. When the agent reads or edits a documented file, a hook names that file’s page, once per page per session. Pages summarize; source is authoritative.
  3. Stop hook. When a turn ends, a local script compares cited evidence with its baseline. Code that only moved gets its line links rewritten. Code that changed makes the page stale, and you see one line per new set of stale pages. 328 ms on a 50,000-file repository.
  4. Update. With "autoUpdate": "remind" (default) you get the reminder. With "auto", the agent runs the update itself in an isolated task. It fixes stale pages first, confirms review pages, and changes only prose the change made wrong.
  5. Sync. sync records the reviewed pages’ new baseline and refreshes the context file. It trusts the caller, so only pages someone checked against current source get synced.

1 Revision note

What the first run taught us

The first map told agents to “read pages before source”. They treated a page summary as the whole answer. One answer said it had “only read the README” and never opened the generator. Recall fell to 80%, against 90% without a handbook. That run is published too.

Two fixes closed the gap:

  1. The map now says “Pages summarize; source is authoritative.”
  2. The run exposed a real coverage gap: one table row covered how the portable skill is generated. A distribution page now covers it, and portable-sync recall rose from 17% to 100%.

A thin page can make an agent less thorough than no page.

Limits of this evidence

  1. One small repository, about 100 files. Agents can search it quickly without help, so savings on large repositories are likely larger, but they are not measured here.
  2. 24 answers per condition. Differences in recall below about 8 points are noise.
  3. The judge is a model. It is blind to the condition, but it can be strict or lenient.
  4. Questions are about architecture and rationale. This does not measure coding tasks.
  5. The final run cost $1.36 for 72 answers, plus about $0.30 for each grading pass. Rerun it before you rely on it.

Reviewed on 8 November 2026 from each project’s own documentation and files. Vendor claims are as published, not verified by the Archlens project.

The model benchmark on A-301 compares Archlens with no handbook, not with these tools.

What no reviewed tool combines

A hard always-loaded budget enforced in CI, model-free drift detection on cited symbols, published answer-quality benchmarks including a failed run, and a built-in tutor for the human (/archlens:learn).

Where others are ahead

OpenWiki and repowise have far larger communities. Code-graph tools answer “who calls this” questions that a handbook does not. Swimm couples individual tokens, not just functions and line ranges.

A-501Learn

Understand the code, not just ship it.

/archlens:learn is a patient tutor. It answers from handbook pages first, reads source to confirm or fill a gap, cites both, and labels inference and unknowns. It runs inline, so you can ask follow-ups.

Four modes

/archlens:learn how are duplicate orders prevented?
Answers from the handbook first, with source links, in at most 150 words. Then one real trace or snippet.
/archlens:learn tour
Walks the reading path one stop per turn and waits before the next.
/archlens:learn quiz data flow
One question at a time about real behavior here. Grades each answer against evidence. Stops after five with a score and the pages to reread.
/archlens:learn changes
Explains what the current branch changes, which flow or data it affects, and why it matters.

While a long task runs, Claude Code’s /btw can answer from the page map already in context.

I-601Install

Three lines in Claude Code. One line everywhere else.

No API key, Node installation, or server is required for the Claude Code plugin. Python 3.9+ on PATH as python3 enables the hooks and checks (the macOS system Python works); the commands still run without it. Your agent’s normal subscription or API usage still applies.

Claude Code plugin

Run these inside Claude Code. Choose user scope when asked, so Archlens works in every project.

/plugin marketplace add tushar-mahalya/archlens
/plugin install archlens@archlens
/archlens:setup

That is all. Setup writes a handbook under docs/architecture/, records a freshness baseline, and from then on the plugin keeps it in step with your edits.

From a terminal, the install equivalent is claude plugin marketplace add tushar-mahalya/archlens then claude plugin install archlens@archlens --scope user. Choose either the native plugin or the portable skill for Claude Code, not both.

Codex, Cursor, Copilot, Gemini CLI, and others

The portable Agent Skill installs with skills.sh. In the project directory, with Node.js 22.20+ and Git:

npx skills@1.7.6 add tushar-mahalya/archlens --skill archlens --agent codex --copy --yes

Replace codex with cursor, github-copilot, gemini-cli, opencode, roo, or devin, or add --global for a user-level installation. Then ask your agent:

Use the Archlens skill to set up architecture documentation for this project.

Setup offers to write the page map into AGENTS.md, which these agents read every session. To write it yourself, set { "contextFile": "AGENTS.md" } in .archlens.json and run:

python <skill-dir>/scripts/archlens.py context --root . --write

Every sync refreshes the block. The written block has no stale flags, because freshness changes between commits; it tells the agent to run the status check before relying on a page. Portable hosts do not necessarily provide Claude’s isolated, manual-only behavior. The skills CLI has its own telemetry; set DISABLE_TELEMETRY=1 to opt out. See installation for adapters and caveats.

Git hooks with pre-commit

Works with any editor or agent. Add Archlens to .pre-commit-config.yaml:

repos:
  - repo: https://github.com/tushar-mahalya/archlens
    rev: v0.3.0
    hooks:
      - id: archlens-check   # links, anchors, diagrams, stale references
      - id: archlens-stale   # on pre-push: fail while cited code changed

Install both stages:

pre-commit install --hook-type pre-commit --hook-type pre-push

archlens-check runs on every commit and fails on structural errors. archlens-stale runs on pre-push and fails while covered source changed after the last sync.

CI check on pull requests

This GitHub Actions job fails a pull request whose code changes leave pages stale. Copy archlens.py into your repository first, for example as tools/archlens.py, or check out the Archlens repository in the job.

name: architecture-docs
on: pull_request
permissions:
  contents: read
jobs:
  freshness:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.13"
      - run: python tools/archlens.py check --root . --summary
      - run: python tools/archlens.py status --root . --fail-on-stale

To rewrite stale pages in CI, run your coding agent’s headless mode with the Archlens update operation and open a pull request for human review. Never let an automated job mark pages reviewed or decisions accepted.

Trust and limits

  • A stale flag means “check this page”. It does not prove the prose is wrong.
  • Code shows what happens, not why a person chose it. Decisions stay proposed until a human accepts them.
  • Python files get symbol-level fingerprints; other languages use normalized line-range text.
  • The benchmark covers one small repository; large-repository and coding-task results are not measured yet.
  • Archlens has no server, no telemetry, and no network calls. Your agent’s provider policy still applies.
  • The writing style is STE-inspired, not certified ASD-STE100.
